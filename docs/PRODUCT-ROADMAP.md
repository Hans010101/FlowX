# FlowX 产品审计与路线图

## 产品判断

FlowX 的核心价值不是“又一个 AI 写作器”，而是把选题、事实素材、质量闸和平台草稿交付串成一个可审计的工作流。产品北极星应从“每天生成几篇”升级为“每天有多少篇合格稿被人低成本确认并成功发布”。

建议主指标：`合格草稿交付数/天`。护栏指标包括绿稿率、人工修改时长、发布预检通过率、同步成功率、事实问题率与单篇 API 成本。

## 本版本已落地

- 赛道归类由“首个关键词命中”升级为多词与词长加权，减少泛词抢赛道。
- 自动发布前检查 Token、CLI、扩展连接和平台登录态，避免无意义等待 120 秒。
- 接通稿件人工编辑，保存后强制重新质检，标题变化安全迁移稿件 ID。
- 浏览器发布器延迟加载，使不使用 Playwright 的核心生成、质检和测试不再被它阻塞。
- 新增核心回归测试、开源许可证、安全说明、贡献规范与真实部署边界。

## 下一阶段优先级

### P0：可靠交付

1. 为发布同步建立结构化状态机：未检查、可发布、同步中、草稿成功、需重连、登录失效。
2. 保存每个平台最近一次预检和同步结果，不记录 Token/Cookie。
3. 为失败任务增加指数退避重试和可操作错误码。
4. 将自动任务日志升级为可筛选运行中心，展示每一步耗时和成本。

### P1：内容质量与效率

1. 记录“人工修改前后差异”和最终采用率，反哺各赛道 Prompt。
2. 同一稿件按头条、公众号、知乎生成平台化版本，而非一稿通发。
3. 增加事实声明清单：把数字、机构、日期抽取出来，逐条关联素材证据。
4. 加入选题收藏、忽略、稍后处理以及批量操作。

### P1：稳定全自动

优先接入有官方 API 的平台，把公众号、百家号做成稳定自动化主路径；头条保留人工最终确认。浏览器自动化只能作为明确标注风险的兜底。

### P2：云端协作版

把工作台、数据与任务执行拆分；云端负责团队协作、审核与队列，本机发布代理只负责使用本地登录态投递。先补齐账户、权限、审计日志和数据删除能力，再考虑公网 SaaS。
